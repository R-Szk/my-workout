# My Workout — Android筋トレ記録アプリ設計書（レビュー案）

作成日：2026年11月3日  
状態：**設計レビュー待ち・未実装**

## 1. 目的

FIT365相模原での週2回の筋トレを継続し、胸板・肩幅・腕の見た目の変化を実感できるようにする、自分専用Androidアプリ。

解消する課題：

- マシン名が覚えられず、種目を記録できない。
- 毎回の入力が面倒だと習慣が途切れる。
- 重量は伸びても、身体の見た目の変化がわかりにくい。
- Uber Eatsの稼働やジムの混雑で、当日の種目順や実施量が変わる。

成功基準：ジムで迷わず記録でき、4週間ごとに記録・写真で変化を振り返れること。筋肉の成長そのものをアプリが保証・診断するものではない。

## 2. 採用した方向性と比較

| 論点 | 選択肢 | 決定・理由 |
|---|---|---|
| ユーザー | 自分専用／一般公開 | **自分専用**。FIT365相模原に特化し、設定負荷を減らす |
| 記録方法 | 自由にマシンを選ぶ／メニューに沿う | **A・Bメニューに沿う**。当日の順番変更・スキップ・追加は可能 |
| 記録画面 | 一覧中心／1種目ずつ | **1種目ずつ大きく表示**。記録操作を最小限にする |
| 保存 | クラウド中心／端末中心 | **端末内＋手動バックアップ**。オフラインと個人写真のプライバシーを重視 |
| 技術 | React Native／Androidネイティブ | **Kotlin + Jetpack Compose**。Android専用に適合 |
| 成果指標 | 重量のみ／重量と回数／独自スコア | **重量と回数**。独自スコアで過剰に単純化しない |

## 3. 初期リリースの対象

### 必須

1. A/Bメニュー開始・進行・中断再開・終了。
2. 1種目画面で実機写真と筋肉図を常時左右表示。画面サイズによっても操作部を圧迫しすぎない配置とする。
3. メイン筋群を赤、補助筋群をオレンジ、その他をグレーで表示。前面／背面は種目で自動選択し、手動切替も可能。
4. セット単位の重量・回数を登録、訂正、取り消し。前回同種目の記録を初期値として提示。
5. 当日の種目順変更、スキップ、追加。スキップは未実施として区別。
6. トレーニング履歴、種目別の重量と回数のグラフ、同重量での回数の比較。
7. 終了サマリー：実施種目・セット数・時間、前回からの記録上の進歩、今日鍛えた筋群。
8. 正面・側面・背面の身体写真を日付とともに端末内保存し、2時点を並べて比較。
9. データと写真のバックアップ書き出し・復元。復元前に内容と上書き対象を提示。

### 初期版では対象外

- アカウント登録、クラウド同期、SNS、公開プロフィール、課金機能。
- 休憩タイマーと通知（要望はあったが現時点では保留）。
- AIによる体型診断・筋肥大判定、カメラによる自動回数計測。
- 消費カロリーや筋活動量を実測値のように推定表示すること。

## 4. 画面設計と操作

### ホーム

今週の実施回数／週2回目標、次に実施するA・Bメニュー、直近の記録更新。大きな「トレーニング開始」ボタン。

### A/Bメニュー選択

種目名とマシン写真の小さな一覧。開始時に当日のセッションを作成し、進行中のものがあれば「再開」を優先表示。

### トレーニング（最重要）

- 上部：メニュー名、種目名、何種目目か。
- 中部：左に実機写真、右に色分け人体筋肉図。部位名（メイン／補助）もテキスト併記。図は説明用であり、計測結果ではない。
- 下部：前回の重量・回数、今回の重量・回数の大きい操作部、セット完了・取り消し。
- 画面操作：次の種目へ、前の種目へ、メニューから順番変更・スキップ・追加。必要なら一覧を一時的に開くが、常用画面は1種目ずつ。
- セット完了のたびにDBへ保存し、アプリ中断後も再開可能。
- 前回値は提案値であり、今回の実績としては完了操作後にのみ確定する。

### トレーニング完了

実施時間、種目数、セット数、同条件での重量・回数更新、鍛えた筋群の前後人体図、今月の実施回数。単純な重量増加のみを「筋肥大した」と断言しない。

### 履歴・成長

日付別履歴、種目別に重量と回数を切替できる推移グラフ。各セットの重量・回数を保持し、グラフは例えば「その日の最も重い成功セット」とその回数を表示。異なる重量間の回数を単純に成長比較しない。総負荷量（重量×回数の合計）は補助指標。

### 身体の変化

体重・胸囲・上腕囲の任意入力、日付付き写真3方向、任意の2時点比較。4週ごとの撮影は推奨するが、通知は初期版必須にしない。写真は初期状態で外部共有されない。

### 設定・マシン管理

FIT365相模原のマシン画像と名称を表示・編集し、A/Bメニューと標準セット数を調整。バックアップ書き出し、復元を提供。

## 5. 初期A/Bメニュー（編集可能なデータ）

**A：胸・肩・背中**

1. チェストプレス：10回×3セット
2. ラットプルダウン：10回×3セット
3. ショルダープレス：10回×2セット
4. ラテラルレイズ：12回×2セット
5. ディップ・チンアシスト：10回×2セット

**B：胸・背中・腕・脚**

1. バーティカルインクラインベンチプレス：10回×3セット
2. シーテッドロー：10回×3セット
3. ラテラルレイズ：12回×2セット
4. プリチャーカール：10回×2セット
5. レッグプレス：10回×2セット

最初の2週間は各2セットから始める。数値は初期プリセットであり、アプリの医学的な処方ではない。

## 6. データ構造（概念モデル）

| エンティティ | 主な項目 | 備考 |
|---|---|---|
| Machine | id, name, imageAsset, notes | 実機写真の参照先 |
| Muscle | id, label, view, regionKey | 前面／背面の図形領域 |
| MachineMuscle | machineId, muscleId, role | role = primary/secondary |
| Routine | id, name | A/B。初期値を編集可能 |
| RoutineExercise | routineId, machineId, order, targetSets, targetReps | 並び順と目標 |
| WorkoutSession | id, routineId, startedAt, endedAt, status | 進行中・完了・中断 |
| SessionExercise | id, sessionId, machineId, position, status | skipped等。メニュー編集後も履歴不変 |
| SetRecord | id, sessionExerciseId, sequence, weightKg, reps, completedAt | セット単位。訂正可能 |
| BodyMeasurement | id, measuredAt, weightKg, chestCm, armCm | 任意項目 |
| ProgressPhoto | id, takenAt, angle, localPath | front/side/back。写真はDB外 |

注意：筋トレ中にテンプレートを変更しても、過去セッションの記録は変更しない。重量はkgで保存し、マシン特有の補助重量などの意味は注記する。

## 7. 技術設計（提案）

- UI：Kotlin、Jetpack Compose、Material 3。
- アプリ構造：単一Androidアプリ、UI／ドメイン／データの責務を分離、ViewModelで状態管理。
- 構造化データ：Room、Coroutines/Flow。
- 設定：DataStore。
- 写真：アプリ専用領域に保存。画面表示では縮小画像を使い、元ファイルは保持。
- 筋肉図：前面／背面の部位別ベクター領域をアセットとして用意し、MachineMuscleの定義により着色。実際の筋活動度は表示しない。
- バックアップ：スキーマバージョン付き記録データ＋写真を1ファイルにまとめ、Androidのファイル選択UIで書き出し／読み込み。破損・不完全データを検証し、復元前に確認。**身体写真を含むため暗号化方式と復元鍵の扱いは実装計画前に決める**。
- マシン画像：提供された一覧を初期候補とし、画像の使用・再配布条件と正確な機種対応を実装時に確認。取得できない場合は自分で撮影した写真やプレースホルダーに差し替える。
- ネットワーク：通常の記録に不要。

## 8. 実装順序の提案

1. Roomのデータモデル、初期A/Bメニュー、サンプルマシン情報。
2. トレーニング開始→セット保存→中断再開→完了の縦断フロー。
3. マシン実機画像と筋肉図の常時表示・前後切替。
4. 種目順変更・スキップ・追加と履歴。
5. 重量・回数グラフと終了サマリー。
6. 身体写真比較・計測値記録。
7. バックアップ・復元、端末上の操作・復元テスト。

## 9. 受け入れ条件

- 機内モードでも全ての通常記録ができる。
- Aメニューを開始し、セットを記録し、アプリを閉じて戻っても続きから再開できる。
- 前回値を表示しても、未完了セットが実績として二重記録されない。
- 順番変更・スキップ・追加が履歴に正しく残る。
- マシン名を記憶せず、写真と筋肉図で種目を識別できる。
- 違う重量での回数を機械的に「増えた／減った」と判定しない。
- 撮影した写真を、日付と方向を合わせて2時点比較できる。
- バックアップを別の端末環境に復元し、記録と写真の整合性が保たれる。

## 10. 残りの判断とリスク

- **暗号化バックアップの方式**：端末内の安全性と、機種変更後の復元可能性を両立する必要がある。
- **マシン写真の権利・入手経路**：画像掲載ページの内容を流用できるか確認し、必要なら自分で写真を用意する。
- **筋肉図の正確さ**：部位ごとの解剖学的区分・主要／補助の対応を検証し、利用可能な素材を用意する。
- **小画面でのレイアウト**：写真と人体図を常時表示しつつ、記録ボタンの押しやすさを実機で確認する。
- **バックアップの動作確認**：端末からの削除や機種変更を想定して復元テストを行う。

現段階は設計案。ユーザー承認後に実装計画を作成し、コードを書き始める。
