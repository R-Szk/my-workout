# My Workout UI・画像アセット Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 既存の記録を保持し、ダークテーマの操作しやすい記録画面・種目に対応した画像と筋肉図・実データの完了画面を実装する。

**Architecture:** 既存の単一appモジュール、Compose、ViewModel、Roomを継続使用する。画像対応と種目別筋群をカタログとして分離し、集計はドメイン層、画像表示とグラフは再利用可能なUI部品にする。既存の保存・重複防止・再開・順番変更処理を利用する。

**Tech Stack:** Kotlin / Jetpack Compose / Material 3 / Room / Coroutines・Flow / JUnit・Robolectric / Android UIテスト。

**Spec:** docs/design.md、docs/implementation-plan.md、2026-11-07のユーザー要件、design-assets/manifest.json。

**状態:** ユーザーの「うん、いいよ」で承認後、実装・検証完了。docs/ui-reference.pngは未配置のため画像との比較は未実施。承認された配色・構成・操作要件を基準に実装した。結果は docs/work-log/ui-assets.md を参照。

## Global Constraints

- 通常利用は完全オフライン。ログイン・クラウド同期は追加しない。
- Room v3の既存データを保持。破壊的な再作成は使わず、変更時は移行テストを行う。
- A/B初期メニュー、ユーザーの編集内容、過去セッションのスナップショットを保持。
- 主筋群は赤、補助筋群はオレンジ、その他はグレー。凡例と部位名も併記。
- 筋肉図は説明用であり、筋活動量や筋肥大の測定結果として表示しない。
- 参考画像や計算用テストデータの数値を本番画面に固定表示しない。
- 権利未確認のマシン写真・派生画像はGitHubへ追加しない。提供済みのステージ内容は無断でコミットしない。
- 画像の縦横比を維持。通常表示はContentScale.Fit。画像内の人体や機器を切り取らない。
- Galaxyを想定し操作領域は最低48dp、主要操作は高さ56dp以上。小画面・大きな文字・キーボード表示を検証。
- 現在のminSdk 36とツールチェーンを維持。Galaxy実機が利用できなければ実機未検証と報告する。
- 身体写真比較・計測値入力・暗号化バックアップは今回の対象外。

## 素材調査と確認事項

- manifestは29件。対応PNGはマシン29枚・筋肉図29枚で、参照先の欠落なし。SVGの筋肉図も29件ある。
- マシンPNGは1000×1000、筋肉図PNGは900×650。提供画像には明るい背景と文字が含まれる。まずは原画像をFit表示し、ラベルはアプリ側でも読める大きさで表示する。
- manifestには利用許諾情報がない。マシン画像フォルダは現在未追跡。ローカルビルドで読み込む構成にし、素材なしのチェックアウトでもプレースホルダーでビルド可能にする。
- 同名別機種: ショルダープレスとレッグプレスにselectorized / plate_loadedがある。機種を名前だけで確定しない。
- 既存ラットプルダウンは複合機の画像候補、シーテッドローは複合機とplate_loadedの候補がある。実際に使用する機種を確認する。
- variableは5件（ディップ・チンアシスト、ファンクショナルトレーナー、スミスマシン、VKRチン、アジャスタブルインクラインベンチ）。これらの筋肉図は対象部位が未着色。
- 種目別プロフィールを用意し、例えばディップスとチンアップ、ラットプルダウンとローを別々に扱う。未確定の過去記録に種目や筋群を推測で付与しない。
- 主筋群・補助筋群はmanifestの文字列だけでは確定できない。SVGの説明文と一次資料を照合し、既存図の色・位置も確認する。必要な種目別図・合成図は提供SVGの人体領域を再利用して作成する。
- 全29件の対応表を扱うが、素材数を理由に既存のA/Bメニューを自動変更しない。

参考: ACEの背筋種目研究解説ではプルダウンとローの主な対象が区別されている。複合機の写真を共有しても、筋群プロフィールと比較対象は分離する。

## 画面構成案

- ホーム: 今日のA/B、実際の今週実施回数、中断中の再開、開始ボタン。既存メニュー一覧・追加フローを維持。
- 記録画面上部: メニュー名・進捗・種目名。マシン画像と筋肉図を横並びの常時表示領域に配置。画面高さに応じて縮小し、拡大表示も用意する。
- 中央のスクロール領域: 前回の記録とセット数、重量・回数の調整、完了済み・未完了のセット。未完了行は表示用で、DBには完了操作時だけ保存する。
- 下部固定領域: セット完了ボタン。キーボードとシステムナビゲーションを避ける。
- 種目編集: 既存の編集シート・追加ピッカーを同じテーマで更新。順番変更・スキップ・解除・追加を維持。
- 完了画面: 実施種目数、セット数、開始から終了までの経過時間（中断時間を含む）、比較可能な記録上の進歩、成長グラフ、実施した種目の筋群、月間実施状況。

## データと比較の原則

- 既存IDや名前を置き換えず、機器画像の対応キーと実施した種目のキーを分離する。種目キーはセッションへコピーし、後からの設定変更で過去の記録が変わらないようにする。
- 複合機での種目選択は記録前に行う。記録済み種目の分類を無断で変更しない。古い未分類記録はそのまま残す。
- DB追加項目はnullableまたは安全な既定値とし、v3→v4の移行で現在位置・セット・スキップ状態も保持する。
- 前回値は同じ種目・同じ負荷種別の終了済みセッションから取得。最終セットと計セット数を区別して表示し、重量が異なる全セットを単一値だったように表示しない。
- 回数の比較は同重量で行う。重量の変更と回数の変更を別に扱い、「筋肥大した」と断定しない。
- 補助重量のあるマシンは通常の負荷と区別。「補助重量が増えた＝成長」と表示しない。
- グラフは同種目ごとに実記録を表示し、重量・回数を切り替える。単位を併記し、1件・0件でも偽の線や値を補わない。
- 実施種目数・月間回数は実際のセットがある記録を対象にする。スキップだけの種目、実績なしで終了したセッションを実施量に加えない。
- 今日の筋群は実施済み・種目確定済みの記録から集計。同じ筋群が主・補助の両方に該当する場合は主を優先。不明な種目があれば不明と表示する。

## Review Focus

- 機種名が編集済み、複合マシン、未分類の古い記録でも、誤画像や誤った前回比較を表示しない。
- ローカル画像が存在しない、壊れている、権利未確認でも、オフラインで記録とビルドを続けられる。
- 320dp幅・低い画面・大きな文字・キーボード表示で、人体図・入力・保存操作が隠れない。
- 初回・前回なし・異なる重量・補助重量・全スキップの完了画面で、架空の進歩を表示しない。
- 中断再開・移行・保存要求の再送で記録が消失・重複せず、過去のスナップショットを変更しない。
