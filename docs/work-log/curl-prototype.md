# カール試作・作業記録

計画: docs/superpowers/plans/2026-11-08-home-workout.md。ユーザーの「うん、いいよ」で承認。
対象は段階1のみ。DB・自宅A/B・他5種目は変更しない。

Ruling: 現在のfeatureブランチの作業ツリーを維持し、新規src/debug配下に試作を隔離する。未コミットの直近修正とステージ済み参考PNG／manifestを別worktreeへ移動しない。
Ruling: MainActivityへの入口追加ではなく、Debug専用Activityとランチャー入口を追加する。通常画面とDBの初期化を一切経由せず、試作を起動・終了できるため。
Ruling: 人体のオリジナル部位図形はSVGを正とし、Compose Canvasで同じパスを読み描画する。参考PNGの画素や輪郭はコピーしない。
Pre-flight: カールだけで独立。後続の種目定義・DB移行との共有インターフェースはこの段階では確定しない。
Baseline APK: 42,698,317 bytes（作業開始時のローカルDebug APK）。


## 実装

- Debug専用ランチャー「My Workout カール試作」を追加。CurlPrototypeActivityはDB／既存ViewModelを参照しない。ReleaseからActivity・描画コード・素材を除外。
- オリジナルSVGを部位別に分け、Compose Canvasで読み込む。参考画像は同梱しない（既存のローカル素材ルート全体がassets対象だったため、参考PNGを除外するビルド設定を追加）。元の参考PNG・ステージ状態は保持。
- 肘の位置と前腕長を固定し、前腕・手・ダンベルを同じ回転で描画する。2.5秒の余弦補間で1往復。画面内の自動再生、絵／ボタンによる停止・再開、姿勢と停止設定の復元を実装。
- LifecycleがRESUMEDでない間はフレームループをキャンセルし、復帰時は中断前の進捗から再開。画面の再構成を毎フレーム行わず、進捗の読み取りは描画フェーズに限定。
- 筋肉図は独立表示。既存BodyMapに省略可能な色引数を追加し、通常画面は元の色、試作はターコイズで上腕二頭筋を表示。小画面用の簡潔なヘッダー、フォーム詳細と筋肉図の拡大も用意。

## カールの不自然な動きの修正

ユーザー確認で肘・接合部・ダンベルの不自然さが指摘された。従来の「固定」の判定はモデル座標だけで、表示された関節の輪郭と一致するかの確認が不足していた。

調査した原因:
- モデルの肘座標自体は固定だったが、上腕の端と前腕の切断面を重ねて回すだけで関節部分の輪郭が変化していた。見かけの肘と回転中心の整合性を画像で検証していなかった。
- SVGのforearmグループに前腕・手・ダンベルが含まれ、全体を-8〜-145度で回すため、ダンベルの軸まで137度回転していた。腕の曲げ伸ばしを、重量の画像平面内の回転として表現してしまっていた。
- 元のSVG座標（手・ダンベルのy=96）と、モデル上の手首84／握り96の対応が描画契約として分離されていなかった。

修正:
- 肩・肘は固定し、上腕の図形を移動・伸縮しない。前腕だけを肘中心に剛体回転する。
- SVGを前腕・手・ダンベルのグループへ分離。手と重量は握り位置へ追従させ、重量の投影軸を水平に保つ。手首と握りの距離12、肘から手首84、肘から握り96を常に保持する。
- data-origin-y=96で手／重量の素材を局所座標へ正規化し、モデルと実描画の握り位置を一致させた。固定の丸い肘接合部で回転する切断面を覆い、接合部が移動したように見える輪郭を解消。
- 描画をCurlCharacter.ktへ分離し、通常のアニメーションと検証用の静止画で同じ描画処理を使用する。
- 体・衣服・顔・脚・上腕のSVGパスと塗り／線の属性が修正前と完全一致することを比較確認。画像の拡縮・変形で動作を補っていない。

検証:
- 肩固定・握りと重量の一致・重量角度・手首から握りまでの距離のテストを先行追加し、未実装APIの失敗を確認後に修正した。
- 実描画9姿勢で、両肘の7×7画素が同じ位置・色に保たれること、ダンベルの金属部分が握り位置から一定の水平位置に描画されることを確認。透明背景も確認した。
- 開始・中間・曲げ終わりの画像と、肩／肘／握りのマーカーを重ねた画像を生成して目視確認。ループ境界では実描画画像も完全一致することを検証する。
- 独立レビューでも実画像2枚とソースを確認し、接合部の切断や手からの重量の脱落などの指摘なし。レビューは読取のみ。
- テスト終了後のAPK再インストールでキャッシュ成果物が消えるため、画像出力はGradleのadditionalTestOutputDirへ移し、Gradleが回収したPNGを検証フォルダへコピーした。

最新の確認画像は build/validation/curl-fix/curl-fixed-poses.png、関節線付きはcurl-fixed-poses-rig.png。動画はmyworkout-curl-fixed.mp4。以前のbuild/validation/curl/の動画・画像は修正前の履歴。
今回もカール1種目だけ。DB・A/B・残り5種目は変更しない。

停止・再開などの既存テストと実描画テストを含む最初の全件実行では、SessionExerciseFlowTest・SetEditingFlowTest・WorkoutFlowTestの3件が失敗した。失敗時のXMLでは一部がランチャー画面へ移っており、アプリクラッシュの記録はなかった。残存する録画・テストプロセスがないことを確認し、この3件を単独実行した結果は全成功。原因をアニメーション変更と断定せず、全件を再実行して検証する。

確認用動画は冒頭の連続再生5秒を切り出したbuild/validation/curl-fix/myworkout-curl-fixed-loop.mp4。元の全長動画も保存している。Macの動画デコーダでフレームを抽出し、ファイルが正常に読み取れることを確認した。

修正の最終検証: 全単体テスト42件、全Androidテスト15件がまとめて成功（失敗・スキップ0）。Debug／Releaseビルド成功、Lintエラー0・警告27。既存データと設定を復元し、修正版をインストール済み。DB・他5種目の変更なし。
