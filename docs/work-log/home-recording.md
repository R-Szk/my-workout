# 自宅6種目のトレーニング記録

2026-11-10。「これを基に、トレーニングを記録できるように」という依頼に対応。

## 変更内容

- `WorkoutRepository` / `HomeCatalog` / `CatalogViewModel`：自宅A/B各3種目、各2セットを登録。初期回数は指定範囲の下限（8回または10回）。`catalogKey` と既存最大IDより大きいIDを使用し、繰り返し起動時も既存の編集内容を上書きしない。新規インストールには旧ジムメニューを登録しない。
- `Entities` / `AppDatabase` / `HomeMigration` / Roomスキーマ5：重量をnullableにし、セッションへ器具区分とメニュー識別子を保存。v4→v5で旧データをコピーし、セットID・保存要求ID・順序・値・日時・AUTOINCREMENTの最大値を保持。v1〜3からの移行も継続。
- `SessionController` / `WorkoutViewModel`：プッシュアップ・スクワットは重量なしで回数を保存。ダンベルは0より大きい有限の重量を必須とする。新規0kg保存禁止は従来のユーザー指定を維持し、移行時に旧0kg記録を書き換えない。
- `HomeScreen` / `MainActivity` / `ExerciseGuideScreen`：A/Bから開始でき、「動作を見る」から選んだ種目で開始することも可能。中断中のセッションがある場合は上書きせず再開。旧端末のみ「以前のメニュー」を表示。
- `WorkoutScreen` / `SetEditDialog` / `SetList` / `RecordText`：自重では重量入力を省き、回数だけを表示。前回値の初期入力、直接編集、セット番号、二重保存防止、中断・再開・終了、当日の追加・順番変更・スキップを維持。自宅の追加候補は自宅6種目。ダンベル重量は1個分、ローは左右実施して1セットと案内。
- `VisualCatalog` / `ProgressCalculator` / `ProgressChart` / `WorkoutSummaryScreen`：自宅キーを旧ジムキーと区別し、自重の実績は重量を作らず回数で比較。ダンベルの重量・回数グラフ、実施種目・セット数、履歴、月間集計を継続。
- 画像アセットや切り替え処理は変更なし。提供された900×900px透過画像、固定領域、ContentScale.Fit、1→2→3→2→1、表示時間設定、筋肉マップを維持。
