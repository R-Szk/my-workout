# メニュー選択と中断トレーニングの再開を明確化

2026-11-10

## 原因

ホームの開始ボタンが、未完了セッションの有無だけで「開始／再開」を切り替えていた。自宅・以前やA/Bの選択は新規開始にしか使われず、旧ジムの中断記録があると選択に関係なく旧記録へ戻っていた。また環境切り替えボタンは切り替え先の名前だけを表示し、現在の環境が分からなかった。

## 修正

- `HomeScreen`：自宅・以前を並べた選択チップ、「表示中」の見出し、開始／再開する環境・メニュー名を表示。
- 中断カードに環境とメニュー名を表示。選択と異なる中断記録を再開する場合は、カードの「中断中のメニューを再開」から明示的に操作。
- 選択が同じメニューなら「トレーニングを再開」。異なる場合は「選択したメニューで開始」から確認ダイアログを表示。中断中の実績を保存して終了し、選んだメニューを開始する。キャンセルでは変更なし。
- `SessionController.finishAndStart`：確認対象の未完了セッションIDを照合し、旧記録の終了と新規開始を同じトランザクションで実施。開始失敗時は旧記録の状態もロールバック。既存セットは削除しない。
- `WorkoutViewModel.switchRoutine`：明示的な切り替えをドメインへ委譲。
- `MainActivity`：SaveableStateHolderでホームの選択を保持。トレーニング／ガイドから戻るときやActivity再生成後も、環境とA/Bの選択を維持。
- DBスキーマ・画像・記録形式は変更なし。複数の未完了セッションを作らない既存ルールを維持。

## 検証

- 先に切り替えの単体テストを追加し、未実装APIで失敗することを確認。
- 旧ジムから自宅Bへの切り替え、旧セット保持、古い確認の拒否、失敗時の中断状態保持を単体テスト。
- Android回帰テストで選択環境の明示、キャンセル、保存して自宅B開始、再生成後の再開を確認。
- 単体54件、Android25件すべて成功。assembleDebug / assembleRelease / lintDebug成功。Lintエラー0・警告30件。
- エミュレーターは機内モードで検証し、終了後に更新版を再導入。実機Galaxyへも記録を保持して更新インストールし、MainActivityの正常起動を確認。
- レビューでホーム離脱時の選択保持を確認し、SaveableStateHolderを追加してAndroidテストで検証。

## 表示名の調整（2026-11-11）

ユーザー指定により「自宅のメニュー」を「自重トレーニング」、「以前のメニュー」を「マシントレーニング」に変更。「表示中：〇〇」の行は削除し、選択チップの色で区別する。中断・開始／再開の説明も新しい名前へ統一。種目・記録・保存形式の変更なし。
