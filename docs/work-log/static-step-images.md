# 6種目の3ステップ画像表示

対象: design-assets/README.md・manifest.json。ユーザーのmy-workout-assetsは当作業ツリーのdesign-assetsに配置されていることを確認。

## 範囲

素材READMEは既存A/B・DB・記録機能の維持を指定している。現在のA/Bはジム用で、自宅6種目へのDB移行はまだ実施していない。範囲の確認を非同期で依頼し、回答がない間はREADMEを優先してDB／A/Bを変更しない。
6種目をホームの「動作を見る」から確認できる画面を追加し、記録画面には明示的なhome.*種目キーに対応する表示を組み込む。自宅メニュー登録／自重記録への移行を済ませたとは扱わない。

## 素材と実装

- 6種目×3枚＝18枚を確認。順序はmanifest記載のstep_1、step_2、step_3。プッシュアップ、サイドレイズ、トライセプス、ワンハンドロー、カール、スクワット。
- PNGはすべてRGBA。元の寸法は692×724／724×724／591×887／592×887。合計3,484,277 bytes。
- app/src/main/res/drawable-nodpi/workout_<id>_step_<n>.pngへバイト単位で同一コピー。元画像の再生成・変形・切り抜き・背景加工はしない。
- ExerciseSteps.ktにmanifestと対応するリソース・表示名・メニュー・主筋を定義。home.*キーだけを解決し、ジムのlateral_raiseなどにダンベル画像を誤適用しない。
- ExerciseStepImagesは静止ImageのLazyRow。ContentScale.Fit、画像に白背景を加えず、1→2→3の左から右へ配置。狭い画面は横スクロール。1枚のカードが表示領域を超えないよう幅を制限。タップで拡大表示できる。
- ExerciseGuideScreenを追加。6種目を選択でき、筋肉図を独立して常時表示。低い画面ではヘッダーを簡略化し、画像・筋肉図・前後操作を残す。
- WorkoutScreenはhome.*キーの場合に3ステップを表示し、既存の重量・回数入力・保存・直接編集・完了ボタンを継続。ジム種目の写真と筋肉図は従来どおり。
- 既存カールの滑らかなアニメを新しい画面では呼び出さない。タイマーや画像の自動切替も追加しない。
- Optional legacy assetsはSyncでmachines/**とmuscles/**だけを生成ディレクトリへコピーして同梱。新PNGをresとassetsに二重同梱しない。README・manifest・previewをランタイムへ混入させない。Debug専用の以前の試作SVGは別のdebug source setを維持。
- AGP9ではTaskProviderをassets.srcDirに渡せなかったため、生成ディレクトリを明示してmergeAssetsとLintへの依存を宣言した。Gradleの依存検証を無効化していない。

## テスト駆動・確認

- ExerciseStepsTestを先行作成し、未実装で失敗を確認後に実装。6種目の順序、3枚の独立リソース、home.*対応、旧ジム／未知キーの非対応を検証。
- Androidの追加テストで、全18枚のリソース寸法と透過ピクセル、6種目の順序表示・切替・筋肉図、320dp×300dpの表示、記録画面での5kg×10回の保存・完了数更新を検証する。
- 最初の順序表示テストは、横スクロール1回だけでは3枚目に届かず失敗。必要な距離をスクロールして順序を確認するよう修正し、追加3件は成功した。低い画面の確認も追加した。
- 記録画面のテストに限り新しい種目を一時登録し、既存セッションへ追加して画像と保存を検証する。保存セット・テスト種目を後始末し、全体のテスト用データは元データへ復元する。
- 独立レビューはCritical／Important指摘なし。18枚のコピー元とコピー先のバイト一致も独立確認。既存の未コミット変更とユーザーのステージ済み素材を保持。

## 往復表示・秒数設定と位置調整版

- ユーザーの追加指定で、横並びから同じ枠の往復切替へ変更。順序は1→2→3→2→1…で端の画像を重複させない。1枚1秒が初期値。
- 表示時間は0.1〜60秒で入力でき、0.5／1／1.5／2／3秒の候補も用意。端末内SharedPreferencesへ保存する。設定中・画面外はタイマーを止める。
- 通常表示と拡大表示は同じフレームを共有し、タイマーを二重起動しない。筋肉図・DB・記録処理は変更しない。
- StepPlaybackTestを先に追加し、未実装で失敗後に実装。往復順、秒数の解析、0等の拒否を検証。Androidでは1→2→3→2→1を実際に観察し、各画像の表示枠が完全一致すること、秒数の変更・再生成後の保持・保存フローも確認。
- 位置調整版の原本はDownloads/my-workout-assets-aligned.zip。プロジェクトのdesign-assets/exercisesの全18枚と一致していることを確認し、drawable-nodpiへバイト一致で差し替えた。全画像900×900、RGBA。人物・足元の再調整は行わない。
- 先行してリソース期待サイズを900×900へ更新し、旧プッシュアップ画像692×724でテストが失敗することを確認後に差し替えた。
- 共通のImage枠とContentScale.Fit、固定の中央揃えを維持。画像ごとのバウンディングボックス計算・自動トリミング・可変ズーム・平行移動・クロスフェードなし。
- 最終の全単体テスト47件、エミュレーターの全Androidテスト20件成功（失敗・スキップ0）。Debug／Releaseビルド成功、Lintエラーなし。

### 実機確認の状況

接続中のGalaxy SM-F966Z（API37）にデータ削除なしのinstall -rで更新。実機の既存データはローカルに退避し、更新前後のworkout_sessions／session_exercises／set_recordsのハッシュが一致した。
実機録画では別アプリの動画小窓が重なり、途中で選択種目も変わっていた。キャプチャには黒いフレームもあり、この録画を位置合わせの検証完了の根拠にはしない。ユーザーへ小窓を非表示にして10秒ほど操作を止められるか確認を依頼し、再確認待ち。エミュレーター確認を実機確認と取り違えない。
